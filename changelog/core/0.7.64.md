## Features

- **keep typed form values across a failed form-action re-render** ([#1582](https://github.com/webjsdev/webjs/pull/1582)) [`9601f96c`](https://github.com/webjsdev/webjs/commit/9601f96c)
  What a person typed now survives a failed form-action re-render. When a
  non-2xx response to a form submission is applied in place, the client router
  restores text inputs, textareas, selects, radios and checkboxes whose
  server-rendered default did not change. A value the server rendered on
  purpose wins. Passwords, files and hidden inputs are never restored, and
  `data-preserve-values="false"` opts a form out. The router's differ also no
  longer reuses one form control for a differently named one.

## Fixes

- **render a boolean in a plain hole on a boolean attribute like ?attr** ([#1580](https://github.com/webjsdev/webjs/pull/1580)) [`d5dc16e6`](https://github.com/webjsdev/webjs/commit/d5dc16e6)
  A boolean in a plain hole on an HTML boolean attribute (`checked`,
  `selected`, `disabled`, `required`, `open`, and the rest) renders exactly like
  `?attr` on the server and the client: `true` writes the empty value, `false`,
  `null` and `undefined` omit it. `aria-*` keeps `"true"` / `"false"`. So
  `<option selected=${i === 0}>` selects only the first option.
