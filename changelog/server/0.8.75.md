## Fixes

- **use the __Host- prefix for createAuth cookies in production** ([#1539](https://github.com/webjsdev/webjs/pull/1539)) [`7388eaeb`](https://github.com/webjsdev/webjs/commit/7388eaeb)
  In production `createAuth` now sends its session cookie as
  `__Host-webjs.auth` and its OAuth cookies as `__Host-webjs.auth.state`
  and `__Host-webjs.auth.redirect`. A browser stores a `__Host-` cookie only
  when it is `Secure`, has `Path=/` and has no `Domain`, so an app on a
  sibling subdomain of a shared hosting domain can no longer plant its own
  session cookie and sign a visitor in to the wrong account. Development
  over http keeps the plain names.

  **Upgrading:** production reads only the prefixed names, so signed-in
  users of a production app sign in once more after this release. A test or
  tool that sets the session cookie by hand in production uses
  `__Host-webjs.auth`.
