## Migrating from 0.9

- **Route modules never ship.** A page, layout or boundary file is never served to the browser and its URL answers 404. `webjs check` refuses a browser module that imports a route file. The elision report's route rows are now `{ file, kind, emits, hints }`, the `webjs.elide` switch is gone, and the doctor check `ELISION_CARRIERS` is replaced by `ROUTE_BROWSER_CODE`.
- **`public/` is served at the site root**, as in Next.js. Drop the `/public/` prefix from every URL that names a file there.
- **Middleware takes the Next.js shape.** The function is the default export, a named `middleware` or a named `proxy`; `export const config = { matcher }` scopes it; it fails closed; `request.cookies` is the `cookies()` store.
- **Form actions behave as in Next.js.** A thrown `redirect()` after a write answers 303, `{ errors }` counts as a failure, and an action declaring `(prevState, formData)` receives the previous result. A success result is shown only on the page its redirect names, and is dropped when that page redirects elsewhere.
- **A schema validator's throw is invalid input on every transport.** A `validate` export that throws an error carrying `issues` (zod, valibot) re-renders a form at 422 with the issues as `fieldErrors`, returns that failure to an RPC caller, and answers a `route()` request with 422 instead of 400.
- **Auth follows Auth.js.** Secure cookies (and the `__Host-` names) follow the auth URL's protocol or `useSecureCookies`, not `NODE_ENV`. Every sign-in and sign-out target goes through `callbacks.redirect`, whose default keeps this origin, so return an identity provider's URL from that callback to land there. `GET /api/auth/signout` shows a confirmation page; only a POST signs out.
- **A missing `AUTH_SECRET` or `SESSION_SECRET`** falls back to a generated `.webjs/dev-secret` only when `NODE_ENV` is `development` or `test`. Anywhere else, unset `NODE_ENV` included, `createAuth()` and `session()` throw until one is set.
